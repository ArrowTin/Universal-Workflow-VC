# MODEL STRATEGY

Model selection is dynamic.

Use the least expensive model capable of completing the current task safely and correctly.

Escalate when justified by:

* complexity;
* risk;
* required expertise;
* context size;
* expected quality;
* verification requirements.

## Switching

Models may be changed during a project.

Before switching:

```text
update task state
→ preserve relevant decisions
→ preserve discoveries
→ preserve verification status
→ checkpoint if necessary
→ switch model
```

The new model must recover through project artifacts rather than relying on the previous conversation.

Model selection should remain subordinate to project requirements and execution rules.
